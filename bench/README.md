# bench — 인쇄기 두 대를 나란히

인쇄기를 바꿀 때는 두 가지를 잰다. 같은 장이 나오는지, 그리고 얼마나 빨라졌는지. 옛 인쇄기는
커밋에서 바로 꺼내 쓰므로 따로 떠 둘 것이 없다.

## 실행

```bash
node bench/serve.mjs
```

`http://localhost:7401`을 열고 **ALL + SAVE**를 누른다. 1~2분 걸리고, 결과는
`bench/results/<실행 이름>/`에 쌓인다. 기본은 캔버스 2D로 찍던 마지막 커밋 `a051816`과 지금
작업 트리를 견준다. 다른 두 커밋을 견주려면 이렇게 한다.

```bash
node bench/serve.mjs --old <커밋> --new <커밋> --port 7402
```

인쇄기가 `createPress`를 내놓으면 WebGL2로, `printSheet`를 내놓으면 캔버스 2D로 알아서 감싼다.
그래서 어느 두 커밋이든 견줄 수 있다. 측정 하나만 돌리는 버튼도 있고, 페이지의
`window.bench`로 콘솔에서 직접 부를 수도 있다.

한 실행이 남기는 것.

| 파일 | 무엇인가 |
| --- | --- |
| `report.md` | 표로 정리한 보고서 |
| `results.json` | 원자료. 보고서의 모든 숫자가 여기서 나온다 |
| `sheets.jpg` | 걸린 판 전체. 왼쪽이 옛 인쇄기 |
| `screen.png` | 망점 1:1. 줄이지 않았다 |

## 무엇을 재나

| 측정 | 보려는 것 | 재는 법 |
| --- | --- | --- |
| 한 장 찍는 시간 | 빨라졌는가 | 1080 한 장. 장마다 GPU가 일을 마칠 때까지 기다린다 |
| 콘택트 시트 | 빨라졌는가 | MOON을 배색 아홉 벌로, 1/3 크기로 |
| GPU 단계 | 시간이 어디에 가는가 | 판 짜기, 분판 래스터와 업로드, 셰이더로 나눈다. WebGL2 인쇄기만 |
| 톤 | 망점 계산이 같은가 | 통 하나를 톤마다 깔고 종이로 나눠 커버리지를 되읽는다 |
| 판마다 | 같은 잉크가 같은 자리에 같은 만큼 앉는가 | 망점 셀 셋 너비인 27픽셀 블록의 평균 차이 |
| 종이결 | 종이가 같은가 | 빈 판의 평균 색과 흩어짐 |
| 이음매 | 루프가 그대로 이어지는가 | 이웃 프레임 차이의 마지막 걸음 z. 씨앗 여섯 |
| 그림 | 눈으로 보아 같은가 | 걸린 판 전체와 망점 1:1 |

롤은 12345, 프레임은 6, 배색은 첫째로 고정한다. 판화는 두 인쇄기 모두 새 쪽의 것을 먹인다.
판화를 고친 커밋과 견주어도 인쇄기의 차이만 남기기 위해서다. 2026-09-17 실행은 이 규칙이
생기기 전이지만, 그때는 두 쪽의 판화 파일이 같았다.

### 시간은 기다려서 잰다

GPU는 일을 받아 두고 나중에 한다. print가 돌아오는 순간 시계를 멈추면 판을 짜는 시간만
잡힌다. 그래서 장마다 한 픽셀을 읽는다. 읽으려면 앞의 일이 다 끝나 있어야 하기 때문이다.

GPU 단계는 이렇게 나눈다.

| 칸 | 무엇인가 |
| --- | --- |
| 판 짜기 | 판화 함수 안에서 쓴 시간 |
| print 호출 | 판을 짜고, 분판 올리기와 셰이더를 GPU에 맡기기까지 |
| GPU 대기 | 그 뒤 GPU가 맡은 일을 마칠 때까지 |
| 셰이더 | 같은 판을 한 번 더 그려 잰 셰이더 한 번. 분판도 값도 그대로 물려 있다 |
| 분판 래스터와 업로드 | 합계에서 판 짜기, 셰이더, 빈 한 픽셀 읽기를 뺀 나머지 |
| GPU 타이머 셰이더 | 브라우저가 `EXT_disjoint_timer_query_webgl2`를 내줄 때만 있다 |

기다려 잰 셰이더에는 명령이 GPU로 오가는 시간이 섞이고, GPU 타이머는 GPU가 실제로 돈 시간만
센다. 둘이 두 배쯤 벌어지는 것이 보통이다. 옛 인쇄기는 끓음을 켜면 인상마다 잡음 표를 새로
뽑느라 찍는 값과 상관없는 시간이 섞이므로, 시간은 HELD로 잰다.

### 종이가 다르면 색이 모두 밀린다

0.24.0에서 종이를 크림색에서 흰색으로 바꿨다. 그 전 커밋과 견주면 판마다의 평균 색과 블록
차이가 종이색 차이만큼 커진다. 인쇄기의 차이는 종이로 나눠 되읽는 톤 측정에서만 그대로 보인다.

### 잡음이 다르면 픽셀이 같을 수 없다

잡음을 만드는 방식이 바뀐 비교에서는 픽셀 하나하나를 견주지 않는다. GRAIN을 0으로 두면
잡음이 망점에 닿지 않으므로 그때만 픽셀마다 견주고, 나머지는 평균과 블록으로 본다.

### 이음매는 두 인쇄기를 나란히 놓고 본다

씨앗을 바꿔도 z가 한쪽으로 모이는 판이 있다. 판화의 움직임이 루프 안에서 고르게 빠르지 않기
때문이다. 그래서 z 하나로 판단하지 않는다. 같은 씨앗에서 두 인쇄기가 같은 값을 내면, 그
이음매는 판화의 것이고 인쇄기와 무관하다.
